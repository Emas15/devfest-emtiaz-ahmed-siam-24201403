# Contest Agent Guidance

Use these instructions only if the organizers permit prewritten AI instruction Markdown files. The official rulebook and organizer clarifications take priority.

- All contest app code must be created during the contest in a new repository. Do not reuse prior code, templates, or old projects.
- Build a browser-only frontend. Do not add participant-controlled backend/serverless code, persistent backend/database/online storage, or secrets. Browser storage and permitted HTTPS browser APIs are allowed under the rulebook.
- Extract and prioritize explicit must-have requirements before editing. Ask important questions during T+0–T+15. Complete the main workflow before bonuses.
- All main user-facing text and interactions must support Bangla and English. Keep core functionality working without AI or an external API.
- Implement in small, reviewable slices. State a concise manual acceptance check and a truthful commit note using the actual prompt for each slice.
- Protect time for at least three timely commits, README/MIT license, public HTTPS deployment, verification, and form submission. Do not rewrite pushed Git history.
- At T+90, stop all code, Git, push, and deployment changes. The late window permits form submission only and costs 10 marks.
- Keep responses and context focused. Use the model capability appropriate to the task, inspect relevant code before changes, and avoid unrelated rewrites.
