# Final Submission Checklist

Use this at T+75 onward. Keep enough time for a final push, deployment, and form.

## Before T+90

- [ ] Every required main task is present and manually checked.
- [ ] Bangla and English modes both cover all main labels, controls, instructions, validation, and status messages.
- [ ] No credential/API key is committed or visible in the live app.
- [ ] No prohibited server, participant-controlled persistent backend, database, or online storage is used.
- [ ] README is complete and accurate; MIT LICENSE is present.
- [ ] At least three commits exist, with required cadence and truthful prompt notes.
- [ ] Final eligible commit is created and pushed before T+90; history has not been rewritten.
- [ ] Public HTTPS link opens without login/install and the main workflow works.
- [ ] Deployment matches the final eligible commit.
- [ ] Record full commit ID, repository URL, live URL, name, and registration number.
- [ ] Submit the official form by T+90.

## At T+90 — hard stop

Stop coding, committing, pushing, and deployment changes. Do not “just fix one thing.” If you use the late window through T+95, it is for submitting the official form only and carries the 10-mark penalty. No code, repository, or deployment changes are permitted.

## After submission

Do not change submitted code, repository, or deployment. Keep the site available through judging/results. Log out of accounts and close the browser when finished.
