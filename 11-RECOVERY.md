# Quick Recovery Notes

## Codex is producing too much or changing too many things

Stop the current request. Ask for one small task, a concise output, and no unrelated refactor. State the acceptance criterion and observed problem.

## Build fails

Copy the first useful error, not the entire terminal history. Ask Codex to diagnose the cause before editing, then fix only that cause and rerun the build.

## External API fails

Keep the required flow usable with organizer sample data and an honest fallback. Never put a private key in browser code. Ask organizer if API availability changes a stated requirement.

## Deployment fails

Check build command/output folder and provider logs. Use the static deployment provider you have already prepared. Notify an organizer if their lab internet/device is at fault. Do not add a participant-controlled backend.

## Push/auth fails

Check remote URL and login while there is still time. Never force-push or rewrite history. Ask an organizer promptly if organizer-provided equipment/network is the cause.

## Time is nearly gone

Stop bonuses and visual polish. Preserve main requirements, both languages, at least three timely commits, public HTTPS deployment, README/license, final push, and form submission.

## API budget warning

Check which account/authentication Codex is using and its live usage display. If using API billing, keep turns short and targeted, avoid repeated full-context jobs, and reserve budget for essential repair. A hard spend limit, if available in your account, is safer than relying on memory. Never share an API key in prompts or commit it.
