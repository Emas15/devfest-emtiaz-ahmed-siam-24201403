# Contest Rules Card

Keep this open throughout the contest. The official rulebook and organizers' live clarifications take priority.

## Must remain true

- Solo contest; all project code is written during the contest, by you or AI. Start from a new repository. No old code, templates, project starter, or anyone else's code. Official starter tools and open-source libraries are allowed by the rulebook.
- The app runs in the browser and is frontend-only. No participant-controlled server/serverless functions, persistent backend, database, or online storage service. Browser storage is allowed.
- External APIs may be used over HTTPS from the browser when CORS permits, but the core app must still work if an API fails.
- Main features work without an AI feature. Any optional in-app AI requires the user's own key entered at runtime; never embed or publish a key.
- All main labels, buttons, messages, and instructions work in Bangla and English.
- The public HTTPS deployment is compulsory by T+90 and must match the final eligible commit. Judges need no sign-in or installation.
- New public repo named `devfest-<registration-number>`. No project code committed before T+0.
- At least one commit every 30 minutes and at least three commits total. Every commit message has a short change note and the prompt actually used; for manual changes write `Manual edit`.
- Do not force-push, rebase pushed commits, delete the repo, or change history.
- Code, commits, pushes, and deployment changes stop at T+90. T+90 to T+95 is for the official form only, with 10 marks deducted. No repository or deployment changes in that window.
- MIT License, required README, and only organizer-provided sample data for testing. Do not use real personal or private company data.
- Log out of GitHub, AI tools, and email when finished.

## T+0–T+15 questions

Ask organizers only. Clarify ambiguous requirements, definitions, edge cases, required outputs, and how they expect sample data to be interpreted. If an answer affects everyone, organizers may announce it to all.

## Stop-and-check triggers

Before using a service, ask: Is this just static hosting or an allowed browser API, or does it store/compute participant-controlled app data persistently? If the latter, do not use it. If uncertain, ask an organizer promptly.

## Conflict handling

The organizers may change the rules. Record any announcement and follow the latest official clarification. This card is a reminder, not a replacement for the official rulebook.
